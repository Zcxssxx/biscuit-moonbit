# 案例：工厂日志的外包排障委托

这是可运行的集成原型，使用虚构工厂、工单和固定测试密钥，不宣称已有客户、真实部署或实际商业收益。

## 接入对象与需求

接入对象是工厂内的日志下载网关。平台把 plant-a 的日志读取权交给外包运维承包商，承包商再委托一次性的工单工具读取 pump-7 日志。工厂审批员掌握独立的审批签名密钥，只同意工单 WO-2026-041。网关预置信任的平台根公钥和工厂审批公钥，检查实际请求后才允许读取。

本例假定工厂网关可连接本地日志存储，但无法稳定访问外部身份服务；工厂审批系统在交付任务前可访问。该需求是本案例的设计前提，尚无真实业务访谈或用户验证。MoonBit 库负责令牌与授权求值，宿主网关负责 HTTP、认证、路径规范化、系统时钟和实际文件读取。

## 角色与权限委托流程

| 角色 | 持有的能力 | 操作 |
| --- | --- | --- |
| 平台签发方 | 根签名私钥 | authority 写入 `right("plant-a", "read")`，并要求指定工厂审批公钥背书 |
| 运维承包商 | 未封存父令牌；没有根私钥 | 离线追加 checks，将子令牌限制为工单 WO-2026-041、`/plant-a/pump-7/logs/` 路径前缀、截止时间以前 |
| 工厂审批方 | 独立审批私钥 | 核对业务工单后，为请求签署 `approval("plant-a", "WO-2026-041")` 第三方块 |
| 工单工具 | 收窄并附带审批块的子令牌 | 随日志下载请求提交凭据 |
| 工厂日志网关 | 可信根公钥、审批公钥、真实请求上下文 | 验签，执行全部 checks，依据 authority 来源的 `right` 判断 read/write，允许后由宿主读取文件 |

衰减让承包商无需拿到根私钥或请求平台重新签发，就能把交给工具的权限缩小。第三方块则把平台授权和工厂审批分开：持有者自己写入同名 approval 事实、或由其他人签名，都不能满足针对审批公钥的 check。网关既要求 authority 的读取权，也要求审批方对当前工单和工厂的背书。

衰减不能取消承包商手里的父令牌。此流程只保证交给工单工具的子令牌保留新增限制；若要求承包商本人也失去原权利，还需收回原凭据或配套撤销机制。第三方签名证明谁签了数据，业务内容是否真实仍依赖审批服务核验。

## 可运行验收

```text
moon run examples/maintenance
```

该程序调用库的签发、衰减、第三方 request/contents、追加、验签和授权接口，并逐项断言结果。任何非预期授权或协议错误都会导致程序失败，CI 执行同一命令。

| 请求/攻击 | 预期 |
| --- | --- |
| 子令牌尚无审批块 | 拒绝 |
| 受信审批后读取指定设备日志 | 允许 |
| 写入日志 | 拒绝 |
| 读取其他设备日志 | 拒绝 |
| 跨工厂读取 | 拒绝 |
| 换用其他工单 | 拒绝 |
| 到期时刻请求 | 拒绝 |
| 持有者在普通衰减块自填 approval | 拒绝 |
| 其他签名者签署同内容 approval | 拒绝 |
| 追加 write 权限事实尝试越权 | 拒绝 |

成功结束输出：`业务验收：10/10 场景符合预期`。演示时钟固定为 2026-11-20，不读取现实时间，所以到期后也可复现。

## 为什么选择此方案

| 方案 | 本例中的接入方式与取舍 |
| --- | --- |
| 中心 ACL/在线鉴权接口 | 很适合实时撤销和集中管理；网关需保持可用的在线链路或维护授权缓存。网络稳定且无转委托需求时，应优先考虑这种简单方案。 |
| 签名 JWT + 业务授权服务 | JWT 可离线验签、携带权限和期限。要让承包商独立收窄权限并组合工厂审批，通常需要另行定义重签/交换和多凭据验证流程；JWT 基础规范未规定本例的追加衰减块协议。 |
| Biscuit | 令牌持有者追加限制块，网关保留原授权约束；工厂只签自己的审批事实，网关按指定公钥信任。适合本例的多方委托和间歇联网条件，代价是更复杂的策略和签名链验证。 |

比较基于 [Biscuit 官方说明](https://www.biscuitsec.org/) 与 [JWT RFC 7519](https://www.rfc-editor.org/rfc/rfc7519)。上表的业务适用性判断是针对本案例前提的工程分析，不表示 JWT 不能构建等价系统，也不是性能基准。

## 实际部署还需要什么

- 网关从已认证会话、规范化路由和服务器时钟提供 site/job/resource/operation/time。不得接受用户自行提交的“ambient facts”。路径前缀判断前要解析 `..`、编码分隔符、符号链接，禁止同一资源出现多套不一致路径。
- 本例仍是 bearer token；泄漏者在限制范围内可使用令牌，签名链不等于调用者身份认证。真实系统需安全传输/存储，必要时绑定会话或设备身份。
- 宿主实现密钥存储、安全随机数、审批身份核验、限流和审计。即时撤销、审批状态变更和防重复使用需要额外状态服务；离线验签不能自动获得最新撤销状态。
- 当前密码依赖未独立审计；本原型没有 HTTP 服务、持久化存储或真实工厂接入，不能按生产交付宣称。

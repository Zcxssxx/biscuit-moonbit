# Biscuit for MoonBit Implementation Plan

**Goal:** Build an interoperable, testable MoonBit implementation of a clearly specified Biscuit subset, failing closed for unsupported features.

**Architecture:** Separate protobuf decoding, signature-chain verification and token proof, Datalog parsing/evaluation, and authorization. Never expose unverified input as authorized. Pin upstream specification and fixtures to exact revisions before claiming conformance.

**Tech stack:** MoonBit; Ed25519; Protocol Buffers; upstream interoperability fixtures; GitHub Actions.

## Work and acceptance gates

1. Pin upstream specification, schema, and official conformance fixtures to compatible revisions; record versions and licenses. Research protobuf and crypto dependencies, targets and audit status. Reconcile the schema with the versioned signature format before implementation.
2. Decode and encode token wire format with bounded input, required-field validation, oneof handling and rejection of unsupported algorithms or versions. Test malformed, truncated and oversized input and official fixtures.
3. Implement v1 signature payloads for authority and appended blocks, chain and proof verification, and secure random key generation through a vetted provider. Test against upstream tokens, wrong keys, mutations, reordered blocks and invalid proofs. Implement sealing and attenuation with interoperability tests.
4. Implement the declared Datalog subset, symbol tables, origin/scoping and resource limits. Unsupported constructs must error, not be ignored. Test deny-by-default, checks, policy ordering, escalation attempts and exhaustion.
5. Provide a real end-to-end runnable example, API docs, support matrix, security limitations and third-party notices. Add CI for check, build, formatting and tests. Run upstream conformance and cross-implementation tests; report passes and exclusions honestly.
6. Complete the competition application with three use cases, publish a public repository and package to mooncakes.io only when working and appropriately versioned; preserve genuine development history. Confirm November schedule and rules with organizers.

## Current status

The outer token parser and Ed25519 v0/v1 signature chain and proof verification are implemented for the documented subset. Upstream Rust fixture tests and a runnable example exist. Issuance, attenuation, Datalog and authorization remain unimplemented; third-party blocks and non-Ed25519 algorithms are rejected. Do not deploy or submit as a completed project.
